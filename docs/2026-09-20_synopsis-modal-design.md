# あらすじモーダルと世界差分の設計

2026-09-20 / WorldBloom_v2。あらすじモーダルの設計はユーザー承認済み。アプリへの接続は未実装。世界差分の表示はユーザー判断により保留。
操作できる画面案：http://127.0.0.1:5552/ （サンプル。外部生成・既存API呼出しなし）

## 方針

候補一覧／格子の上に、単体・複数で共用するモーダルを開く。生成前確認→生成中→結果を同じ枠内で切り替える。
添付画像の独立したジョブ進行ページへは通常遷移しない。候補の選択・絞り込み・スクロール位置を維持する。
あらすじは選ぶための補助操作であり、採用や本文生成は同時に行わない。

## 入り口と状態

| 状態 | 表示 | 操作 |
| --- | --- | --- |
| 生成前 | 「あらすじを作る」、今回の対象N件、候補名・世代、生成設定の折りたたみ | キャンセル／N件のあらすじを作る |
| 受付確認中 | 「生成を受け付けています」。対象と要求を固定 | 連打不可。再度新しい要求を送らない |
| 生成中 | 「あらすじを作成中」、完成X/N件、候補別の待機・生成中・完成 | 生成を停止…／閉じて候補を見る |
| 完了 | 「あらすじができました」、成功件数、候補別結果 | 閉じる／完成したあらすじを読む |
| 一部失敗・停止 | 成功分は保持し、未生成・失敗を個別に表示 | 成功分を読む。失敗理由は詳細から確認 |
| 結果不明・復旧待ち | 失敗と区別して表示。確認できた最後の状態を維持 | 詳細・復旧へ。自動再生成なし |

単体の場合は1行、複数の場合は同じリストを複数行表示する。1件でも確認段階を維持し、クリック直後には課金・生成しない。
通常の候補行選択とは別に、既存のあらすじ準備モードで対象を指定し、主ボタンでモーダルへ入る。
既に成功した候補や結果不明・復旧待ちを黙って再生成せず、今回の対象数と除外理由を表示する。
呼出し上限Lが対象Nより小さいときは「対象N件／上限L件」。主ボタンも「上限L件で作成」にする。
プロンプトのみの設定は「プロンプトを保存」に切り替え、あらすじが生成されるとは表示しない。

## 閉じる・戻る・停止

- ×、Escape、「閉じて候補を見る」はモーダルを閉じるだけ。生成ジョブをキャンセルしない。背景クリックでは閉じない。
- 閉じる前後も、候補画面のフッターに「◌ あらすじ生成中 1/3件・開く」を残す。同じジョブを再表示する。
- 完了時もモーダルを勝手に開かず、「あらすじ3件完成・結果を開く」と控えめに通知する。
- 「生成を停止…」はモーダル内の確認領域へ展開。入れ子のモーダルは作らない。既存の停止APIへ1回送信し、「停止を要求しました」と表示する。確定するまで「停止しました」と断定しない。
- 停止しても完成したあらすじは保持。処理中の1件は結果不明になる場合があり、その状態を隠さない。
- あらすじを読む操作は、単体なら元の候補、複数ならユーザーが指定した完成候補（未指定時は先頭）を候補詳細の「物語」で開く。フィルターを勝手に変更しない。表示外の候補はその旨を表示して明示的に開く。
- 生成中に候補閲覧へ戻ることは許すが、判定・メモの編集可否は既存の実行中ロックに従う。
- ページ再読込・別タブでは既存ジョブ一覧から該当runのあらすじジョブを照合。サーバーの状態を正とし、記憶したIDだけで生成中と決めない。

## 見た目

最大幅720px、画面高から上下余白を引いた最大高。ヘッダーと下部操作を固定、長い候補一覧だけ内部スクロール。
スマートフォンでは左右16pxの余白、幅100%に近い表示。本文16px前後、既存のゴシック体・緑・生成開始のオレンジを使用。
主情報は対象候補、完成件数、次の操作。長いjob ID、経過秒、詳細な上限、バックエンドの生の状態名は前面に置かない。
生成率は実際の完了件数から算出。1件の生成中に根拠のない％や完了予定時刻を作らない。
フォーカスをモーダル内に制限し、閉じたら起点のボタンへ戻す。進捗の通知は控えめに行い、背景スクロールを止める。

## 既存処理との接続案

- viewer/output_pages.py の build_confirmation を、従来HTMLと読み取り専用のモーダル計画取得の共通処理にする。ここからジョブは開始しない。
- モーダル用の計画レスポンスは画面に必要な候補・公開版・選定版・設定要約・固定request・警告だけ。秘密情報やコマンドは返さない。
- viewer/static/sifting-workspace.js の単体リンク／複数選択フッターから、共通の synopsis-modal.js を起動する。サーバーで確認した候補IDとあらすじ対象を固定する。
- 明示開始で既存 POST /api/jobs。受理後はリダイレクトをせず、job_id・output_idをモーダルの監視状態へ渡す。
- GET /api/jobs/{id} と GET /api/outputs/{id} を共用の監視器から読み、候補別結果を表示。閉じている間は間隔を広げ、完了時に終了する。
- 通信不明は生成失敗と同一に扱わず、最後の確認状態と接続中断を表示する。受付不明の明示再試行は同じrequest_id。結果不明の再生成は既存の試行ID確認を維持する。
- 完成したあらすじはSHA確認済み本文をcandidate_idへ結び付けて差分更新する。セル単位で別世代に流用しない。
- 同じ実行の進行中ジョブがある場合は新規要求を作らず、既存ジョブを開く案内にする。
- ジョブURLと生成確認URLは履歴・直接リンク・JavaScript無効時のために残し、表示部品を共用する。通常フロー用の新しい独立ページは作らない。

## 世界の変化を組み込む案（保留）

ユーザー判断により、世界変化の表示は今回の実装対象から外す。以下は将来の検討用として残し、再開の指示があるまで実装しない。

新しい常設タブや一覧列は増やさず、候補詳細の既存「実験データ」の先頭に「世界の変化」を置く。
初期表示は「初期設定との差分を見る（3件）」の1行。開くと変更のあるカテゴリだけを表示する。
カテゴリは概要／人物／場所／時間／初期物語など、世界設定と同じ分け方にする。追加・変更・削除を区別し、前→後を短く見せる。変更のない項目は畳む。
長い文章の差分や記録の出典は、さらに必要なときだけ開く。生のJSON比較は主表示にしない。

比較は次の2つを混ぜない。

1. 実行開始時に保存した世界 → その候補を実行した世界（世界拡張の影響）。Siftingで表示する候補単位の差分。
2. 実行開始時に保存した世界 → 現在編集中の世界（実行後のユーザー編集）。実行条件側で必要時に確認する別の比較。

現checkoutでは ConfigStore._bundle が保存入力とSHAを検証しており、初期設定の根拠に使える。
一方、gapengine/genome.py は行動方針・ルールのゲノムで、execution/evolution_worker.py の候補記録もそれを保持している。これを世界設定全体の差分とは呼ばない。
今回の調査では、候補ごとの世界拡張結果を再現・検証できるデータ契約は確認できていない。別作業の世界拡張実装と、候補ID・初期世界の参照とSHA・適用後世界または検証済みパッチ・スキーマ版を接続できた時点で実装する。
拡張が実行中にも発生する方式なら、候補開始時の適用世界と終了時状態も分ける。単なる人物移動・好感度変化を世界設定変更と混同しない。
比較記録がないときは「比較情報なし」。確認できない状態を「変更なし」と表示しない。記録がない既存runへ架空の差分を付けない。

## 今回の実作業と確認

- 候補一覧のツールバーの表示崩れは実アプリで修正済み。件数タブと操作列を分け、絞り込みとあらすじ準備を36pxの同じ高さに統一。共通detailsの罫線・余白を打ち消す。
- 1280×720と390×844で操作位置・高さ、絞り込みの開閉を確認。
- モーダルは独立した操作サンプル。生成前→生成中→閉じる→完了通知→あらすじ閲覧を確認。実LLMは呼び出していない。
- 世界差分は配置サンプルと実装条件の検討まで。世界拡張の実装には変更を加えていない。
