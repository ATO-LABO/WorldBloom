## 3. 残る改善項目（すべて P3。差し戻しではない）

### 3-1. 所持品を「一部だけ」失うと代償欄に内部パスが出る

`gapengine/explanations.py` の label 辞書は体力と評判しか持たないため、所持数 3→2 のような部分減少は `".".join(path)` にフォールバックし、読者向けパネルに「桃太郎 の resources.assets.きびだんご -1」と出る。値は正しく、分類（kind=item）も優先順位も契約どおりなので誤情報ではないが、全数喪失側の「◯◯ が所持品 X を失った」と同じ概念が 2 通りの見た目になる。

再現: momotaro seed=0 で 11 件。既存の探偵・恋愛ログは全員が所持数 1 のため発火せず、9 ログ 1620 決定では 0 件。
修正: resource 分岐で `kind == "item"` のとき専用の文面を使う（3 行程度）。

### 3-2. 実装済み 28 動詞のうち 12 個が「未対応の行動（guard）」と表示される

`viewer/explanation_ui.py` の `VERBS` は 16 語。concede / craft / disguise / donate / guard / negotiate / plant / rescue / sabotage / sacrifice / trial / withdraw が未登録で、いずれも `gapengine/scenes.py` の `VERB_LABELS` には日本語訳がある。付録 E の「未知の行動は識別子を保って包む」は未実装動詞への保険のはずが、momotaro では決定の約 14% で常用経路になる。

修正: `VERBS` に 12 語を足すだけ（`scenes.py` は触らない＝付録 E の「scenes/synopsis は変更しない」を守れる）。

### 3-3. 比較フォームで 0 件・1 件のまま送信すると生の JSON が返る

修正: `app.js` で送信前に件数を見るか、`compare_page` の件数エラーを `document()` で HTML 化する。

### 3-4. 詳細ページの `<pre>` に CSS が当たっておらず、狭い幅で横スクロールする

`app.css` の折り返し規則は `.explanation-comparison pre` にしか効かず、同じ markup を最も多く出す詳細ページには祖先セレクタが無い。実装者の自己検証は比較ページ中心で、詳細ページの狭幅が抜けている（報告書自身が「モバイル実機は未検証」と述べている領域）。

`elif after < prior:` を `after != prior` に変えると増加（利得）まで代償として表示されるのに、131 件が全て通る。テスト名は `cost_direction` を名乗るのに fixture に増加ケースが無い。

## 4. 反証で落とした主な指摘（記録）

差し戻さない判断の根拠として残す。

- **「他主体への記録済み効果を無視して該当なしを出す」（P1 として提起）** — 棄却。当該の隣接 `learn_fact` は `before == after` で、主体フィルタを外しても転機候補にならない。表示文「この選択に該当する転機候補イベントなし」は広い探索範囲でも字義どおり真。付録 E は「同じ主体・ターン」を明文で指定している。さらに提案された修正を入れると、ランの終端 `ending` が直後に書かれる無関係な NPC の決定に転機候補タグが付き（240 ラン中 174 件）、契約 §2.5「時間順に並んでいることは因果の証拠にしない」に正面から反する。**元の不具合より重い誤表示を作る修正案だった。**
- **「未記録の内部進捗を持つ verb で該当なしを出す」（P1 として提起）** — 棄却。`no_change` は absent を**狭める** AND ガードであって判定の根拠ではない（主条件は転機候補イベントの有無）。契約 §3 の absent は「該当種別のイベントが無い」と定義されており、「状態変化が無い」ではない。提案された修正（observe / investigate を supported から外す）は付録 A が意味を確定済みと宣言している verb を常に不明へ落とすもので、契約と衝突する。規模の主張も実測で約 6 倍の過大評価だった。
- **「回帰 131 件が再現しない・決定論テストが断続的に失敗する」** — 棄却（原因特定済み）。`engine/sim.py` の `_engine_source_hash` は `@lru_cache(maxsize=1)` で、serial（親プロセス）はスイート開始時の値を使い続けるのに対し parallel（spawn）は子が `engine/*.py` を読み直す。**スイート実行中に `engine/*.py` が 1 バイトでも書き換わると、このバイト一致テスト 3 件だけが落ちる**。今回はレビュアーの変異試験が並行していたため踏んだ。HEAD 由来の性質で本差分とは無関係。私の単独実行では 131 件 OK。
- **「契約 §2.1(a)・§4.3 が約束する『結末の到達可否の反転』が未実装」** — 棄却（ただし §5 に注記）。§2.5 の確認済み転機の定義は選言（候補条件の成否**または**結末の到達可否）で、実装は前者を出典付きで満たしている。結末述語は原理的にログに無い（`affinity_cap` はログ中 0 件、述語は world.yaml 側）ため、満たせない側を「転機なし」ではなく不明に落とすのは §2.5 と §3 が明示的に命じている扱い。`limitations` にも明記されている。
- **「同席者 present が画面に出ない」** — 棄却。契約 §5 の 002 への確定事項は「決定時の場所」しか要求しておらず、present は 002 が契約外に自発的に足した付加情報。抽出 JSON には出ている。
