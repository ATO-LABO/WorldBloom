## 2. 差し戻す 2 件

### 2-1 [P2] 実行されなかった後続行動が「executed_later_action」として facts に入る

**対象**: `gapengine/reader_summary.py` の `build_packet`、turning links ループ末尾の `add("executed_later_action_not_total_causal_proof", fact, [next_line])`。

後続行動の fact は `result` を問わず kind に `executed`（実行済み）を名乗る。`result == "invalid"`（前提不成立で実行前に棄却＝**そもそも起きていない**）でも同じ kind でパケットに載り、LLM には「実行された後続行動」として提示される。

**再現**: `extract_explanation(r"C:\Projects\WorldBloom-local\runs\exp10-detective\g0\ind-1\seed-4\layers.jsonl", experiment="exp10-detective", cell="II|low")` → `build_packet`。facts が 9 件になり、f4〜f7 がすべて `result: "invalid"` の confront（L141/154/160/166）。元行は `"effective": false`, `details.reason = "prerequisite_unsatisfied"` で delta は全空。コーパス走査では confront/invalid が 666 件。

**なぜ問題か**: プロンプトは探偵編について「誰を疑っていたか→証拠を見直す→疑いの先→告発」を中心に書けと明示的に告発を促す一方、`result: "invalid"` が「起きなかった」を意味することはどこにも書かれていない。モデルが「その後、探偵は丙を告発した」と書けば**起きていない出来事の断定**になり、refs は正当なので `parse_summary` を通過し、ハッシュ拘束もすべて成立する。最後の防波堤が人手の照合だけになる。

本プロジェクト自身の語彙とも矛盾する。`gapengine/scenes.py` の `RESULT_LABELS` は `invalid` を「実行条件を満たさなかった」と定義している。

**現時点で表示は正しい**（試作 3 セルは exposed / exposed / paid_off のみで非成功が無い）。ただし 007 を 3 セル以外へ広げた瞬間に P1（誤情報の表示）へ昇格する。1 行で塞げるものを残す理由がない。

**修正**（レビュアーの検証で修正案が 1 度洗練されている点に注意）:

```python
if out.get("result") == "invalid":
    continue
```

当初案は「成功値（`exposed` / `paid_off`）のホワイトリスト」だったが、これは誤り。`_confront` は `misjudged` も返し、これは**ハンドラが実際に走った結果**（評判 −0.1、相手からの好意 −0.3、確信度の半減、`misjudged` マーカー）で、記録上まぎれもなく起きた出来事である。ホワイトリストにすると、この実在の告発とその代償が読者向け説明から丸ごと消える。判別軸は「成功したか」ではなく「**ハンドラが実行されたか**」で、それは `result == "invalid"` で一意に切れる。

回帰テストは `exp10-detective/g0/ind-1/seed-4` の形（links 複数 + `result: "invalid"`）を fixture 化し、あわせて **`result: "misjudged"` が落ちないこと**も固定すること。

### 2-2 [P2] 格子ページで LLM 生成文が無標識で表示され、根拠付き四項目の短縮表示が消える

**対象**: `viewer/reader_ui.py` の `short()`、呼び出し元 `viewer/pages.py`、`viewer/static/app.css`。

### 3-3 [P3] 複数のアサーションが意図した検査とは別の理由で通っている

## 5. この機能の性質について（採否の前に理解しておくべきこと）

**意味の正しさは信頼境界であって、機械的保証ではない**。`artifact` と `.review.json` を書ける者は任意の文を表示させられる。これは実装の穴ではなく設計上の前提で、実装者も `verified_summary` の docstring（"Integrity plus explicit editorial review; not an automatic semantic proof"）と試作文書に明記している。機械が保証するのは「表示文が、承認された成果物と一致し、その成果物が特定のパケット・プロンプト・元ログに結びついている」ことまで。

したがって、この機能で読者に届く文の正しさを支えているのは、

1. パケットのホワイトリスト（世界の真値・policy・未解決の伏線を入れない）
2. プロンプトの禁止事項
3. 形式検証（引用 ID、文数、長さ）
4. **人手による意味の照合**

の 4 層で、うち 4 が最後の防波堤である。今回は Codex が 3 本を文ごとに照合し、私が独立に読み直して問題を見つけられなかった。**この体制は 3 本だから成立している**。自動適用へ広げる際は 4 が外れるので、1〜3 を強くする必要がある（§2-1 はその 1 に該当する）。
