# Shared working copies, version 1

A working copy is not a validated proposal or a runnable world. The existing new-world draft page has explicit Save, list/resume, uncertain-save lookup and save-as-separate-copy controls. These operations never call an AI, publish into projects, or run the engine.

`WorkspaceStore` keeps a versioned raw editor buffer and raw pre-generation name/overview/time inputs in control/world-draft-workspaces. Incomplete names, duplicate/empty time slots and invalid JSON may be saved; execution validation remains a separate, explicit action. Raw proposal text is never normalized, field-filtered or rewritten on save. Unknown envelope versions are refused without overwrite and shown as unavailable in the list.

Each save uses an expected revision and a unique request ID. A stale writer gets 409 and retains its input; a separate copy can be saved without replacing the other writer. Exact response-loss retries reconcile with a receipt/record, while read-only lookup is the UI path for uncertain outcomes. Revisions before replacement remain in history. No automatic retry or overwrite occurs.

The AI proposal token and working-copy token have separate lifecycles. Resume first reads the linked proposal, then overlays the exact human buffer and revokes approval. A cancelled/adopted/missing proposal can become a new unchecked proposal only through an explicit check action. `stage` does not validate, invoke AI or publish; structural/reference validation and the existing live alignment review remain mandatory before adoption. Unrelated AI changes remain constrained by draft_revisions. In-item dialogs must be reflected/cancelled before the outer working copy can be saved; their uncommitted fields are not silently discarded.

An optional first-save source_world_id captures native project files and referenced template directories as immutable base64 bytes with hashes. It does not shrink them into the bounded proposal schema. Forking copies that exact snapshot, even after the live source changes. This is source preservation, not an import/apply or full native-file editing UI: snapshots are never sent to AI or merged into a world by these endpoints. Existing worlds/subjects/templates and frozen run settings are not modified. ZIP import, full native editing and a unified coauthor screen remain separate work. The snapshot is capped at 8MB, working JSON envelope at 256KB; native publication never bypasses the existing validation/adoption path.

API: GET /api/world-draft-workspaces (metadata only), GET /api/world-draft-workspaces/<id>, POST same ID with revision/request_id/content and optional source_world_id or source_workspace_id on creation. All writes use the existing same-origin/client boundary. IDs are canonical lowercase UUID hex; no user-provided file path is accepted. Reading never auto-migrates or repairs a saved record.

Failure behavior: atomic replacement retains the previous complete record; preimage history is written before replacement. The latest record embeds its save receipt for recovery if the receipt sidecar write fails. An uncertain result is looked up; differing server/local copies are not auto-merged. The API does not delete drafts or history. Existing prototype/session tokens are not rewritten until the user explicitly saves/resumes.
