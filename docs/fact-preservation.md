# 事実を保つ文章生成：最初の実装単位

基点は develop `52a456408d5ec8c534b7de9d49892b019c06fd78`。
設計資料は https://chatgpt.com/space/page_d031905e65e08191bfc7f18d32a9f0af 。

## この単位の範囲

版付き補助資料、入力選択、あらすじ／本文用プロンプト、既存の生成ジョブへの接続、結果の保存と再検査を追加する。
原ログ、固定設定、story_v1 の素材・構成案・検証器は書き換えない。
story_v1 の結末必須条件を維持する。新しい `facts_v1` は別の契約で途中場面を扱う。
固定例 F0〜F5 は人が構成した試験入力であり、既存シミュレーターが生成したログではない。

## 記録と保存

`details.fact_record` の明示された型付き記録を読み、原ログの物理行、行の SHA、ログ全体と固定設定の SHA を補助資料側へ保存する。
旧ログにない区別は `unsupported_extraction` とする。`message_read` を到達・気づき・理解に分解したふりをしない。
世界事実、主張、到達、気づき、理解、認識、行動の各段階、状況、合意を別の型で扱う。
認識は到着予測・理由評価・意図推測を分け、理解した主張と更新前後・規則版を要求する。
主張を分割しても連絡 ID を保持する。この単位では認識更新量の計算や独立証拠の加点を実装しない。

入力は採用 ID・必須 ID・非開示 ID・視点を明示して選ぶ。依存する前提を残し、非開示の根拠が必要な選択は拒否する。
本文入力はあらすじだけに依存せず、選択した固定記録を保持する。
共通条件と作者の表現設定を分け、表現設定の変更は別の不変パッケージとして保存する。

## 生成ジョブ

要求版 3、`pipeline=facts_v1`、`fact_refs` を追加する。版 1 と 2 の意味は維持する。
受付時に run・candidate・ログ・config・input manifest の束縛を確認し、準備時にも確認する。
入力パッケージと選択済み入力を出力フォルダの `inputs/facts/<candidate>/` に保存する。
プロンプトはジョブが固定した runtime から組み立て、既存 OutputStore に全文と SHA を保存する。
モデル・生成設定・応答・試行記録も既存ジョブの保存経路を使う。
テスト用の固定応答は使い捨てのテスト用 runtime の transport にだけ設定する。製品に疑似モデルのバックエンドを追加しない。

## 検証の限界

形式検証は JSON の形、根拠 ID、必須参照を確認する。
型付き意味の検証は主体・時点・型・内容・依存関係の変更を検出する。「話者の主張」を「世界事実」に変えた対応記録は失敗する。
自由文が対応記録と同じ意味かどうかは、この検証器では証明しない。
正しい根拠と対応記録を付けて誤った自由文を書いた場合も `semantic_review_status=not_reviewed`、`human_adoption=pending` を保持する。
自動検証の成功を作品の採用や意味の正しさと表示しない。
表現設定の矛盾検出は限定した語句の検出に留まる。一般の自然文指示の矛盾は自動判定できない。

## 残る段階

新しいシミュレーションから型付き記録を生成する接続、通知や認識更新の規則、行動候補の両立判定、作者向け UI は後続の実装単位。
確率・遅延・認識更新量は未決であり、この実装で数値を追加しない。
実モデルの品質評価は別段階。既存の実モデルへの呼び出し、公開、push、PR、merge はこの単位に含まれない。

```
python -B -m unittest discover -s tests -p test_story_pipeline.py -v

```

Windows の制限された実行環境では TEMP/TMP を書き込み可能な作業フォルダへ向ける。
