    結末固定¶

    WorldBloom は「面白い出来事が起きるように世界を調整する」のではなく、先に結末を1つ固定し、そこにたどり着く道のりだけを進化で探すという順序を取ります。世界の作り方や登場人物の初期状態を、結末に都合よく寄せることはしません。

    結末は述語で書く¶

    結末は、7層構造が共有する述語の語彙を使った条件式（when）として、世界の定義に書きます。

    実物（projects/momotaro_plus2/world.yaml）の形式で示すと、ending: はこのようなリストです。when は述語文字列か {agent, goal} のどちらかの形式を取れます。

    ending:
  - id: homecoming_shared
    when: "holds(桃太郎, 鬼ヶ島の宝物) and zone(桃太郎) == '村' and '還元' in phase"
    label: 宝を村へ還元し、皆で喜びを分かち合った
  - id: homecoming
    when:
      agent: 桃太郎
      goal: attained
    label: 鬼退治を果たし、宝を村へ持ち帰った

target_ending: [homecoming, homecoming_shared]

    holds（所持）・zone（居場所）・stance（関係性）などの述語を組み合わせるだけで、恋愛（相互の stance がしきい値以上）や探偵（confront で正解を言い当てる）の結末も同じ仕組みで書けます。1つの世界に複数の結末候補を書いておき、そのうち target_ending に指定したものだけが実際の到達判定に使われます。

    到達判定のタイミング¶

    判定は layers.jsonl に記録された ending イベントを見ます。あるランで、target_ending に指定した ID の ending イベントが1件でも記録されていれば、そのランは「到達した」と判定されます。ランが早期に打ち切られるのは、主人公の生命状態が dead（死亡）になった時点のみです。

    到達しなかった個体の扱い¶

    固定結末に届かなかったランは、QD 格子のアーカイブには入りません。世界側を結末に合わせて曲げない代わりに、アーカイブは到達ランだけの「入場ゲート」として働きます。ただし到達しなかったランも無駄にはならず、結末の条件式のうちどこまで満たしたか（連言のうち成立した割合や、しきい値までの近さ)を測る「整形適応度」を持ち、次世代の親を選ぶときにだけ使われます（アーカイブには漏れません）。

    到達率¶

    同じ遺伝子でも、複数の固定シードで走らせた結果、結末に届くランと届かないランが混在します。「到達率」は2つの粒度で記録されます。1つはエリート個体の到達率（その個体を複数シードで走らせたうち到達した割合）で、QD 格子の各セルのエリートに付き、同点のタイブレークに使われます（gapengine/qd.py）。もう1つは世代全体の到達率（その世代の全個体・全シードのうち到達した割合）で、summary.json に記録され、世代を追った推移のグラフに使われます。世界側を結末へ拘束しない設計上、到達率は一般に低く出ます——これは探索が最大化しようとする目標ではなく、あくまでアーカイブに入るための条件です。GA の選択圧が世代を重ねるごとに到達率を押し上げていくこと自体が、「結末固定」という設計の実際の効き目です。
