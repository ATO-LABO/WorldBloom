# CLI終了後の一時フォルダー清掃

3a66062のWindows/Python 3.13全体試験は、CLI境界のTemporaryDirectory終了時にWinError32で1件失敗した。同じheadの再実行は4環境成功したが、初回失敗を断続的な問題の証拠として残す。終了要求やJob Objectの終了確認と、作業フォルダーを削除できることは別の条件である。

専用の試験プロセスが作業フォルダーをCWDとして保持すると、CLI側の所有するプロセスが終了していても、同じWinError32を再現できた。対象の一時フォルダーだけをNtQueryInformationFileのFileProcessIdsUsingFileInformationで調べ、保持するPIDを照合した。元のCIで保持していたPIDは過去のログに記録がなく、特定したとは扱わない。Job Objectの[ActiveProcesses](https://learn.microsoft.com/en-us/windows/win32/api/winnt/ns-winnt-jobobject_basic_accounting_information)は所有するプロセスの終了確認に使い続け、別のプロセスやOSのフォルダーハンドルを消したことの証明にはしない。

現在はCLIの終了確認後、標準入力・標準出力・標準エラーと、Windowsの直接の子プロセスのハンドルを明示的に閉じてから一時フォルダーを清掃する。Windowsの共有違反・アクセス拒否で清掃できない場合だけ、既存の10秒の終了予算の残りで解放を待つ。モデルの呼出し、CLIの再起動、リクエストの再送は行わない。元の呼出し・終了確認の期限は延長しない。

清掃が予算内に完了しなければ元のエラーを返す。所有するプロセスの終了が未確認、または一時フォルダーが別のパスやリンクへ変更されていれば、削除せずContainmentErrorで止める。他のプロセスを終了させたり、ファイル権限を変更して強制的に成功と扱う処理はない。

任意のCI計測では、ハッシュ化したフォルダー識別子、CLIのPIDと終了コード、ハンドル解放、清掃拒否時の保持PIDとOSエラー、清掃の成否だけをcli-workspacesへ保存する。プロンプト、コマンド引数、設定、認証情報は記録しない。フォルダー保持者の診断は対象の一時フォルダーに限定し、プロセス全体を走査しない。計測APIが非対応の場合もその結果を記録し、清掃の成否を成功へ置き換えない。

再現と確認は`python -B -m unittest discover -s tests -p test_cli_workspace_cleanup.py -v`。CLIを1回だけ実際に起動し、ハンドル解放後の清掃、永続する保持の有限失敗、終了未確認時の保持を検証する。元の成功・時間切れ・非ゼロ終了を含む境界試験の期待値も維持する。
