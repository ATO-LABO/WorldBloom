PR #5 の正式ソースと独立 AIT-134 修正（基点 `ec5f0d1505b3d0c5f02a6e5481f631cee03582fa`、draft PR #7）上の、時間設定画面・設計下書きの独立変更です。未取得の三系統統合 ZIP の内容や一致は検証していません。

## 状態と画面遷移

完成した範囲は、`/worlds/{id}` → 左ナビ「時間」の基本画面、特別日ごとの編集状態、設計下書きの保存・再読込、検証と適用プレビューです。

基本画面は常に「期間と通常日の時間設定 → 特別日一覧」。特別日0件では空状態を表示し、初日・最終日の常設カードはありません。追加・行編集から独立した「一覧・選択中の編集・適用プレビュー」の3列に移ります（狭い画面では縦に配置）。保存成功・取消で基本へ戻り、保存失敗では入力を保持します。保存中の連打は抑止します。

未保存の取消、別の特別日選択、左ナビ移動、世界切替、編集状態からのブラウザ戻るには「編集を続ける／変更を破棄して戻る」の確認があります。ページ自体から離れる操作にはブラウザ標準の未保存確認を使います。

通常設定には複数の名前付き時間帯、曜日別・休日別の差をフォームで入力できます。特別日は単日・日付範囲・初日／最終日からの相対日、優先順位、対象時間帯、有効状態を持ちます。開始日が未定でも今日の日付で補完しません。初期の09:00〜17:00は設計用の入力例であり、既存エンジンの時刻ではありません。

## 保存契約と既存データ

現行エンジンは `world.time.days / slots` の離散スロットです。下書きは専用 sidecar `projects/{id}/time-settings-draft.json`（schema_version 1）に、プロジェクトと下書きの revision を確認して atomic replace・fsync で保存します。構造上安全な意味無効入力は保存できます。世界 ID、パス、サイズ、階層、JSON・schema 構造、symlink、競合編集は別途拒否します。存在する空の下書きは破損として扱います。

設定構造は `period: {start_date,end_date}`、`normal: {bands,weekdays,holidays}`、`specials: []`。曜日キーは月曜0〜日曜6。休日は `{date,bands}`。時間帯は `{id,name,start,end,overnight,interval_minutes,event_id?}`。特別日は `{id,name,enabled,priority,selector,bands}`、selector は `kind: date|range|first|last` と `start/end/offset` を持ちます。同じ時間帯 ID へ通常設定→曜日→休日→特別日の順で適用し、特別日では大きい優先順位を優先します。最高順位同値・異なる値は競合とし、両行・対象欄を示し、該当時間帯の適用を未確定にします。

既存の予定された出来事の追加・行編集はそのまま使用できます。設計の時間帯は既存イベント ID を参照し、時刻の二重保存はしません。IDの対象イベントを変更するとプレビューも更新します。既存スロットが「朝」等の名前だけなら時刻は未確定とします。

この保存は `world.yaml`、人物、既存イベント、旧run、ログ、resume参照を更新しません。実エンジンの入力 blobs/records と実パーサの days/slots が保存前後で一致することを試験しました。既存の世界複製操作は sidecar と設計版も複製し、複製先の編集は元の世界に影響しません。設計版の元 world_revision は保存されます。既存の YAML 限定 ZIP 取込へこの JSON を渡す機能は追加していません。下書き・設計版のバックアップは世界ディレクトリと sidecar を一緒に保管してください。

## 検証と版の区別

日付逆転・期間外、0／負／非整数の判断間隔、夜跨ぎ未指定、名前付き時間帯の重複、翌日への夜跨ぎ重複、同順位競合を検出します。最後の短い区間も失いません。プレビューは最大366日・合計10,000区間、設定期間は最大3660日、時間帯定義は全体100件です。打切りを表示し、競合・重複の検証は全設定期間で行います。

「設定を確認」は変更概要・適用元・エラーを表示します。有効で参照先が確定した設定だけ「設計版を記録（実行には使えません）」から内容アドレス付き不変 JSON を `time-settings-versions/{sha256}.json` に記録できます。既存版の改ざんは拒否します。記録は実行可能を意味しません。設計版からの編集復元・適用は今回未実装です。

**部分完成／未対応：** 可変判断間隔・日付別の時間エンジン、実行用の新版確定、人物の予定／約束エンジン。`finalize` は常に `unsupported` を返し、実行設定を作りません。UIも実行用確定を未対応として無効にします。複数日の下書きを1日に縮めたり、設計版で既存runの参照を差し替えたりしません。

API は GET `/api/worlds/{id}/time-settings`、POST 同URL（下書き保存）、POST `/validate`、`/archive_design`、`/finalize`。POST は既存のJSON本文・同一origin・`X-WorldBloom-Client`境界を通し、保存／設計版記録／実行確定要求には書込可能な実行管理設定が必要です。読み取り専用モードは閲覧・検証のみです。
