# Lossless world drafts and scoped forms

Existing world/ZIP intake preserves every project file and referenced template bytes in an immutable source snapshot. No narrow proposal conversion is used. ZIPs are limited to 10MB compressed/8MB expanded, reject traversal, aliases of paths, case collisions, device names, links/encryption and ambiguous roots without partial publication. A single project wrapper or repository-style projects/<id> plus templates bundle is supported. Unknown fields and binary files are kept. Existing registered worlds must use the current format. Invalid or legacy ZIPs can be stored and exported as original. Their world contents are unavailable for editing, validation, and publication.

Native form buffers store scoped operations separately from original bytes. They may be unfinished, save/reload with expected revisions and request IDs, and fork without overwriting the other writer. Known world/person YAMLs are reserialized only when semantically changed, preserving unknown sibling fields; untouched files remain byte-identical. Comments/formatting in a changed YAML may differ, while exact originals remain exportable. Duplicate-key or oversized world/person YAML is retained read-only rather than lossy parsing.

Forms cover ordinary-turn days/time-band names, scheduled event identity/day/slot/targets and supported effects/forced action, per-action people and permitted time bands, native goal description/item/destination and personal commitments. Existing proposal goal-condition forms remain available. New concern conditions can be authored with zone, inventory or knowledge adapters, achieve/maintain and observed/public evaluation. Other existing conditions remain selectable; no text-to-priority inference occurs. Advanced calendars/execution modes are retained and unsupported edits are refused. Rest remains unrestricted. Changing a constraint does not enable an OFF action or bypass other runtime requirements.

Explicit checking materializes only in a temporary repository, constructs the native input path, validates time/deadline/event references and people/action policy, and returns a digest and warnings. No model/simulation/GA starts. Explicit publication repeats validation and template-byte checks, then atomically stages a new world ID. Original worlds and shared templates are never overwritten. An edited already-published draft must fork to publish another world. Export includes every project file plus template dependencies. A publication receipt guards retries after a lost response; differing existing output is never replaced.

The shared forms for generated proposals make scoped structural edits without a model call. Pending section edits block outer saving/navigation until reflected/discarded. Multiple forms retain independent pending guards; stale captured data cannot overwrite later human edits. API writes retain the existing same-origin/client boundary. Native import accepts a 14MiB JSON envelope for a ZIP up to 10MiB compressed/8MiB expanded; native saves accept 2MiB. Proposal/workspace/forms endpoints accept 1MiB; other control endpoints retain 64KiB caps.

The world creation page links to a coauthor workspace for resumable proposals and native imports. Optional type/intro notes accompany generation, review and scoped revision and are saved as creation-context.json on adoption. These notes are metadata, not inferred engine constraints or a mandatory threat-story template. Future type IDs and outline keys are retained. Old browser-only intro notes are read only on an explicit import action.

Imported native worlds use the same entry page and lossless scoped forms, with a native AI proposal adapter for time, existing scheduled events, action actor/time constraints, goal fields and registered personal priorities. Candidates cannot add/delete files, people, events or conditions, alter rest/ON/OFF, or write arbitrary paths/expressions. The existing provider transport is reused only on explicit request. Structural/runtime validation precedes preview; exact target and field allowlists, native snapshot retention, version checks and explicit apply/save protect manual edits. A general arbitrary-file native-world AI editor is not implemented. New bounded proposals retain their original revision/diff contract. Real provider quality and live model execution are not tested. Advanced calendar edits, arbitrary native goal logic and unknown schema editors remain unsupported while their source content is retained.
