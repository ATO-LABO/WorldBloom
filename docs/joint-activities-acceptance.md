# 共同行動と共同作業の受入条件

[設計書](joint-activities-design.md)を実装する際の試験条件です。ここに挙げた実行試験は設計段階ではまだ実施していません。[契約例](design-examples/joint-activities-contract.json)の数値は整合性を検査するための例として定めたものです。

## 契約と予約

| 識別子 | 条件 | 確認する結果 |
|---|---|---|
| JA01 | 合意済みの操船者一人と同乗者三人が一隻を使う | 一つの共同区間が成立し、四人の時間と一隻を確保する |
| JA02 | 必須の役割が不足する | 開始せず、位置、材料、体力を開始前から変更しない |
| JA03 | 同じ人物を二つの人数枠に入れる | 設定または提案を拒否する |
| JA04 | 参加者が定員を超える | 開始しない。人物を自動で置き去りにして開始しない |
| JA05 | 役割、知識、行動権限が不足する | 該当する人物をその役割で開始させない |
| JA06 | 合意後に役割、対象、費用、資源、時間が変わる | 古いバージョンの合意で実行しない |
| JA07 | 同じ人物や道具を重なる時間へ予約する | 競合を記録し、全員・全資源の部分予約を残さない |
| JA08 | 同じ船を別名で登録して予約する | 同じ資源参照へ解決するか、別名の設定を拒否する |
| JA09 | 合意の返答がまだ届いていない | 主催者の計画では条件付きとし、予約や受諾済みの効果を発生させない |

## 時間と順序

| 識別子 | 条件 | 確認する結果 |
|---|---|---|
| JA10 | 選択順の途中で必要な合意がそろう | 次の共通の開始境界へ予約し、先に行動した人の枠を再使用しない |
| JA11 | logical_stepで開始1、所要時間1 | 終了2。区間1以上2未満は全員が占有され、終了後に次の行動を選べる |
| JA12 | minuteで開始12、所要時間20 | 終了32。全員の時間を20分として扱う |
| JA13 | 同乗者の体力消費を0にする | 時間は占有する。体力の消費と、世界で定義された回復を二重計算しない |
| JA14 | 完了、破壊、期限が同じ時刻にある | 契約で定めた境界順序を再現し、物理的な完了を期限判定より先に処理する |
| JA15 | 個人の仕事や通信の終了と共同区間の開始が同じ時刻にある | 終了を処理してから空き時間と受信済みの情報を確認する |
| JA16 | 異なる時間単位を混ぜる、終了が観測範囲外になる | 暗黙の変換や即時完了をせず、候補または設定を拒否する |

## 進捗と成果

| 識別子 | 条件 | 確認する結果 |
|---|---|---|
| JA17 | 技術担当と補助担当が毎分1の共同作業を20分行う | 作業量は20。参加者二人を理由に40へ増やさない |
| JA18 | 同じ作業へ個人の加算処理と共同の加算処理が接続される | 一つの実記録と書き込み先に限定し、二重の加算を検出する |
| JA19 | 技術担当が毎分0.1、補助担当が毎分0.05を消費する | 20分でそれぞれ2と1を消費する |
| JA20 | 診断者が工程完了後に離れる | 完了した診断は保持し、作業全体を未着手へ戻さない |
| JA21 | 診断は完了したが次の担当者に内容が届いていない | 作業の完了と知識の受信を区別し、必要な情報の取得を計画する |
| JA22 | 交換は終わったが確認工程が残る | 設備を修理済みと確定しない。例では37分の確認完了で確定する |
| JA23 | 共同作業が一つの部品を完成させる | 完成品は一個で、定義した持ち主または置き場所へ一度だけ反映する |
| JA24 | 別の対象へ、以前の診断や途中の作業量を使おうとする | 対象と入力のバージョンの適合を確認し、自動で成果を流用しない |

## 中断と復元

| 識別子 | 条件 | 確認する結果 |
|---|---|---|
| JA25 | 開始時に一人の体力が不足する | 全員の開始を中止し、開始費用を取らない |
| JA26 | 交換開始12、必要な人が19に離れる | 進捗7と個別の消費0.7、0.35を保持して中断する |
| JA27 | 20に代役で再開する | 新しい区間で残量13を進め、33に交換を終える。古い区間を再開済みにしない |
| JA28 | 任意の役割が離れ、残る役割だけでも成立する | 区間を区切り、残る人の条件と合意を確認して次の区間へ進む |
| JA29 | 航行中に船が破壊される | その時点の航路上の場所、消費、人物の状態を保持する。出発地や目的地へ戻さない |
| JA30 | 中断した区間に材料を開始時に消費していた | 消費済みの材料を返却しない。完了時に消費する材料なら未消費として扱う |
| JA31 | 同じ進捗、完了、再接続の通知が重複する | 作業量、費用、移動、成果物を再適用しない |
| JA32 | 進行中に保存し、別のプロセスで復元する | 時刻、人物の占有、資源、進捗、消費、知識を連続実行と一致させる |
| JA33 | 参加者の参照、資源、確定時刻、世界のバージョンが壊れた保存を読む | 復元を止め、不足分を推測して実行しない |
| JA34 | 実装上の例外、または世界内の事故が発生する | 前者は境界の書き込みをまとめて戻し、後者は実際の結果を保持する |

## 人物の判断と汎用性

| 識別子 | 条件 | 確認する結果 |
|---|---|---|
| JA35 | 主催者には有利だが、参加者の高い優先順位や譲れない条件と衝突する | 参加者が拒否または撤回でき、主催者が強制して開始しない |
| JA36 | 同じ行動へ、異なる目的を持つ人物が参加する | それぞれの目的を保持する。共有する最終目的を自動で追加しない |
| JA37 | 遠くの人物の所在、持ち物、返答、私的な拒否理由が変わる | 未受信の情報で計画や表示を更新しない |
| JA38 | 桃太郎、船長、文化祭の参加者へ名前と対象を対応付け直す | 物語名による分岐なしで同じ契約を検証できる。競合のない条件で因果関係が対応する |
| JA39 | 既存の文化祭の作業と約束へ接続する | 寄与と履行を管理する記録を一つにし、受諾だけで作業完了や約束の履行を確定しない |
| JA40 | 新機能を有効化していない既存の世界を同じ種で実行する | 行動の選択、時刻、乱数の消費、既存の記録形式を保持する |
| JA41 | 候補の組み合わせが探索の上限に達する | 打ち切りを表示し、成立不能や目的の失敗確定と区別する |
| JA42 | 共同区間、人物別の表示、作業全体、目的の結果を読む | 一つの原記録にたどれ、各人物の負担と未回答・中止・中断を区別できる |
| JA43 | 同じ乗り物の参加者、別の乗り物の人物、遠隔の共同作業者がいる | 同乗者の所在の観測と到着を区別する。別の船の内部や遠隔の人物の状態を自動で共有しない |
| JA44 | 役割の寄与を毎分2と1、集団の上限を毎分2にして10分作業する | sum_role_ratesで作業量20とし、上限のない30や固定速度の例と混同しない |

## 実行試験の組み合わせ

共同移動、共同修理、途中で担当を替える修理を、ターンまたは分の実行に接続します。同じ定義を別の人物名・場所名でも読み込み、個人の目的からの候補生成と実際の効果を確認します。

移動と修理の各例について、正常完了だけでなく、開始前の拒否、人数不足、資源競合、途中の変化、保存と復元を組み合わせます。通常実行の記録と、条件を一つずつ変える実行試験を分けて保存します。

画面を実装した段階では、共有デザインに従い、デスクトップと狭い幅で一覧、参加者の内訳、原記録、スクロール、キーボード操作、未回答や競合の表示を確認します。物語の面白さやGAでの候補の広がりは、実行の成立と別に評価します。
