## 起動

PythonとPyYAMLが既にある同じPCで、復元したソースのルートに移動する。新規ダウンロードやインストールはこの検証では行っていない。

`settings.json` に以下を保存する。認証情報は不要。既存の別checkoutの設定を上書きしない。

```json
{"output":{"default_backend":"ollama","ollama":{"model":"qwen3.8:27b-q4_K_M","base_url":"http://127.0.0.1:11434","think":false,"options":{"num_ctx":2048,"num_predict":1600,"temperature":0.2},"limits":{"max_calls":1,"call_timeout_seconds":300,"wall_seconds":360,"max_saved_response_bytes":64000}}}}
```

```powershell
New-Item -ItemType Directory -Force .local-qwen\runs | Out-Null
python -B -m viewer.server --repo . --runs .local-qwen/runs --control .local-qwen/control --port 8773 --world-draft-live
```

`http://127.0.0.1:8773/worlds/new` を開く。概要を入力し、生成された人物・場所・関係・目標と既定値を確認する。必要なら下案JSONを修正し検証する。確認チェック後に採用すると新規世界が保存される。実行は別操作。

通常の上記CLIでは明示クリックごとにローカル生成を行う。今回の測定専用 `run_live.py` は一プロセス一回までに制限した。測定中の8773サーバーでは生成枠を使い切っているため、結果の閲覧用として使用する。

`--world-draft-live` を省略すれば実生成は待機、`--world-draft-mock` は明示された固定モック。両者を実モデル生成と混同しない。

## 変更と限界

既存の新規下案実装（独立コピーdb6e018、公開main 08471d24a730ae49db96b20de67148139c08f368由来）へ、Ollama JSON出力指定、形式例の内容流用を避ける指示、ローカル呼出し上限300秒を追加した。外部APIの上限60秒は維持。
このコピーはgit archiveから復元した独立ブランチ `codex/qwen-local-new-world`。元checkoutの読取拒否対象にはアクセスしていない。

初版は「品物を場所へ届ける」目標に限定する。基本ルール、7日間・4時間帯、数値特性0.5・基礎値50を補う。人物関係の数値は下案として人が確認する。構造と参照の検証は、物語の自然さ、到達可能性、一般の概要に対する生成成功率を保証しない。今回の実生成成功は小さな一例だけ。
