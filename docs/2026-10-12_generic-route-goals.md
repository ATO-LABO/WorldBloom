# 汎用目標と時刻付き経路探索の最小実装

基準: main `82d32d93ce4cedf10407f030f69f19dc93f702ea`。クラウドの独立した checkout/branch で作業し、ユーザー PC を使用しない。AGENTS.md と .agents/skills は checkout・親ディレクトリ・環境の .agents に存在しなかった。Linux の UI ジョブ管理には変更を加えない。

## 目標と探索の責務

`route_goals.GoalSpec` は達成条件の定義・参照検証・判定を担当する。配送の `Subject.goal.target/deliver_to` も「本人が品物を1個以上所持」「本人が配送先にいる」という AND に変換できる。既存配送の意味は維持し、受取人への譲渡・donate は自動追加しない。目標条件と、達成のための行動を別の責務にする。

`route_paths.survey` は設定を解決して探索器を選ぶ。明示的な `goal` がない既存世界は従来の配送後方計画・逐次再計画を使う。明示的な `goal` は `route_search` の時刻付き有限探索を使う。同じ GoalSpec が配送手順の完了判定と時刻探索の完了判定に使われる。新しい設定は調査専用で、Policy・遺伝子・通常シミュレーションの行動選択を変更しない。

## 設定例

世界固有の `projects/<world>/route.yaml` があればそれを設定全体として使い、なければ従来の `templates/<genre>/route.yaml` を使う（部分 merge はしない）。世界設定から「経路の目標を入力・検証」を開くと、登録済みの人物・場所・品物・情報・時刻を入力して検証・保存できる。YAML と既存 GET `/api/worlds/<id>/routes` も引き続き利用できる。

```yaml
goal:
  actor: 主役
  all:
    - {predicate: at, zone: 体育館}
    - {predicate: holds, item: 衣装, quantity: 1}
  time: {mode: at, day: 1, slot: '15:00'}
search:
  max_expansions: 5000
```

対応する条件:

| predicate | 引数 | 判定 |
|---|---|---|
| at | zone、任意の subject | その人物の場所が一致 |
| holds | item、任意の subject/quantity | 所持数が quantity 以上（既定1） |
| knows | fact、任意の subject | その情報が本人の knowledge にある |

`subject` 省略時は actor、actor 省略時は主人公。actor は登録済みの任意の人物を選べるが、探索で能動的に操作するのはその1人。他人物は初期状態と対応済み予定イベントに従い、都合よく動かさない。条件リストは非空の AND。OR/NOT、好感度・体調・感情、任意の自然言語や Python 式は未対応。未知の参照・余分なキー・不正数量・未登録時刻は設定エラーとして返す。

## 時刻、早着、待機

文化祭サンプル `samples/route_goals/cultural_festival` は world.time を1日・06:00〜17:00・30分刻みの23境界として定義する。既存の世界の時刻・性格・初期状態をこのサンプルに合わせて書き換えない。

| time.mode | 意味 |
|---|---|
| any（または time 省略） | 設定期間内で初めて条件を満たした時点で終了 |
| by | 指定時点を含む期限までに条件を一度満たせば成功 |
| at | 指定時点で全条件を同時に満たす必要がある |

行動は境界 t から t+1 まで1スロットを消費し、結果は t+1 に反映する。開始境界でも達成判定する。終端17:00では判定するが新しい行動を始めない。時点一致に対して早着しただけでは成功せず、待機するか他の合法な行動を経て判定時点まで進む。待機は明示的なモデル行動で、1スロット・所持品と場所を維持する。早着後の安全な継続は実際の物語全体について保証していない。

境界では予定イベントの効果を適用した後に目標を判定する。対応は `move_to`・`grants_item`・無値情報の `grants_fact`、開始前の slot:null。これらは入力世界のイベントに限る。判定時点に体育館から教室へ移されるなら、早着していても失敗となる。force_action・stress_delta その他未知の効果は無視せず `unsupported`。日替わりイベントや乱数を含むイベントはモデル外。

最小実装は1日内・昇順で等間隔の HH:MM スロットのみ。複数日・夜間の長い間隔、可変長行動、時刻をまたぐ複合条件、時刻ごとに開閉する辺は今後の拡張。

## 探索モデルと保証

`deterministic_slot_projection_v1` は静的な有向隣接辺移動・待機・調査入手/無値情報学習・製作を列挙する。移動は actor の verbs・genre と range.zones/exclude・本人の requires_item 所持を確認する。仲間の車両借用はモデル外。調査は sources の count を必要な調査回数、max を入手回数上限とし、製作は材料数量を消費して1個製作する。craft_zone と必要 knowledge を確認する。学習は区域が一致する無値情報源のみ、人物由来の情報源や証拠からの信念更新はモデル外。wait はモデルでは常に可能。

このモデルは全エンジンの効果シミュレータではない。体力・phase rules・関係・交渉・戦闘・通常行動の重み・他人物の自律行動は射影から除外する。辺の cost はエンジンでは主に移動コストであり時刻ではない。このモデルでは隣接1辺を1スロットと明示定義する。実エンジンの move は複数辺の到達先を1行動にできるため、エンジン全体の最短行動数とも一致を主張しない。

探索状態は `(tick, 全人物の zone/inventory/knowledge/gathered/gather_progress)`。入力を deepcopy して探索し、元の World/Subject/YAML は変更しない。候補は安定した順に列挙し、rng/world.truth は読まない。時刻を含む重複排除により、待機を無限ループと誤判定しない。

BFS は各遷移が正の同じ1スロットであることを前提に、最初の達成について **モデル内の経過スロット数（待機を含む）** の最短性を保証する。時点一致ではどの成功手順も指定時点まで同じ経過時間になる。非待機行動の最少回数、最少 stamina cost、最も自然な経路、全状態の最短性は保証対象ではない。time/状態の射影と遷移列挙が完全なこのモデルに限る保証であり、将来の重み付き時間モデルには Dijkstra 等の別探索器が必要。概算 h は BFS に使用しない。

全探索でキューが空になれば、設定期間とこのモデル内だけの到達不能を判定できる。予算を超えて未探索状態が残る場合は到達可能性を未判定とする。予算は展開状態数で既定5000・上限100000。終端と目標を予算より先に確認するため、予算を使い切った時点の既達成を取りこぼさない。大きな分岐世界には計算量・メモリの限界があり、モデル・予算のラベルを結果に残す。

## 結果ラベル

| status | 意味・表示 |
|---|---|
| found | モデル内の最短経路（待機を含む経過スロット数） |
| unreachable | 設定期間・対応モデル内では到達不能。世界全体の証明ではない |
| cutoff | 探索上限で打ち切り。到達可能性は未判定 |
| unsupported | 未対応の時刻構成・予定イベント効果 |
| invalid_config | 不正な目標・探索設定 |
| ok | 既存の概算配送手順を生成。最短保証なし |
| no_plan | 既存の概算モデルで手順が見つからない。到達不能の証明ではない |
| no_goal/no_route_config | 目標/設定なし |

`shortest_guaranteed: true` は必ず `optimality_scope: elapsed_slots_in_model` とモデル名を伴う。配送は常に false。従来の `h` は概算として維持し、手順生成の反復・60手打切りは cutoff。配送の完了判定も品物所持と配送先一致で行い、h==None や上限到達を成功と誤認しない。表示側はモデルの確定境界をそのまま使い、配送の概算タイムラインと区別する。

## 互換性と次の実装

配送型の取得・対決/交渉・後方計画・Policy は従来どおり。route.yaml を既に持つ世界に新しい goal を強制しない。一般目標をシミュレーションの ending/Policy に自動接続しない。目標調査の結果と人物が自然に選ぶ通常経路は用途が異なる。

次の段階は遷移 adapter の分離と実エンジンに沿った時刻定義、複数日・force_action・状態依存ルール、戦闘/交渉の確率的達成条件。追加機能があって初めて全状態や期待値の保証を議論できる。本人や世界の設定を勝手に変えて成功経路を作らない。

## AIT-134 独立目標エディタ

この変更は PR #5 の `b787363a64a5d4dd490edf7f0fd5682290304b2c` 基点の独立修正。Linux PR #4 や未取得の文化祭統合 ZIP と一致・統合済みとは主張しない。Choice GA の再開は含めない。

入口は `/worlds/<id>` の目標入力リンク、編集ページは `/worlds/<id>/goal`。非空の AND（上限100条件）、操作人物1人、条件ごとの人物、at/holds/knows、品物の正整数数量、any/at/by を扱う。検証・探索は未保存の入力を評価し、保存は世界専用 route.yaml のみを atomic に更新する。人物の配送設定、通常 Policy、結末、過去の設定版・run は変更しない。

`GoalSpec.to_input_dict()` は zone/item/fact を明示する入力用 serializer。説明用 `as_dict()` の value/legacy は保存しない。any は mode だけを保存し、at/by は登録時刻と day を保存する。legacy adapter は明示目標へ勝手に変換しない。

API は GET/POST `/api/worlds/<id>/route-goal`、POST `/api/worlds/<id>/route-goal/validate`。書込は既存の job_store・HTTP 境界で保護する。世界・人物・世界専用 route の有無と bytes・ジャンル YAML の revision を確認し、競合時は409で拒否する。世界専用設定を初めて作る場合はジャンル設定全体を複製して goal のみ変更する。旧配送へ戻すと goal のみを除き、他の経路設定を保持する。入力 config snapshot は世界専用 route.yaml も凍結する。

取消・再読込・離脱は未保存変更を確認する。失敗した保存・競合では入力を保持する。閲覧専用は編集/保存不可。未対応条件・不正な保存済み目標は黙って置き換えずエラーを表示する。時間モデルが対応しない設定は保存を拒否し、unreachable/cutoff は目標が不正とは扱わない。モデルの判定範囲を結果に表示する。

検証は `tests/test_route_goal_editor.py`（serializer round trip、早着/待機、参照/数量/時刻拒否、HTTP、保存再読込、revision、atomic故障、旧設定・凍結入力の保持）、`node tests/test_route_goal_input.js`、既存の route/timeline 回帰。実ブラウザによる10シナリオの証拠は実装成果の検証 archive に保存する。統合 Windows・3系統統合版の検証とは区別する。
