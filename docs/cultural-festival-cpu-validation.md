## パターン0の可行性と実走の区別

`pattern0_plan.yaml` は**手書きの通常出席計画**で、生成ログではない。
1辺1枠、完了を次枠冒頭に反映する契約を前提に静的に確認し、エラー0。
8時出発→8時30分校門→9時部室。午前に衣装準備、蓮の相談・蒼の了承、練習。
11時30分体育館へ移動→12時リハ。展示協力後、14時に体育館に戻り、14時30分と15時に在場。
この計画は2枠の共同運搬を使わない。静的チェックは native runtime 成立の証拠にはしない。

実走した `native-diagnostic` は、対応済みの隣接移動・待機・宛先付き同室知識共有だけを時間指定で選んだ診断。
実装した Policy は候補にある行動のみを選び、強制イベントを使わない。未提示の行動があればエラーにする。
準備や相談の未対応部分を省いたため、この診断をパターン0とは呼ばない。
診断では8時に始めた移動が8時中に完了し、蒼は8時に校門、8時30分に部室へ到着する。
これは承認された完了タイミングと異なる。各枠内の逐次実行により知識も即座に反映される。

15時の行動前の蒼は体育館に在場、蓮も在場。衣装・練習・音響・出演拒否は不明（null）。
在場を出演成功と扱わず、不明を『在場だが出演しない』と分類しない。
15時に移動を選ぶ境界テストでは primary は不在のまま。後続の到着と分けて記録する。
実行失敗は native script の失敗と契約の未対応を別記する。

## ログと再現方法

`native-diagnostic/layers.jsonl` は実際の engine イベント・選択ログ。
`observations.json` は検証者専用の時点ごとの位置・知識監査。位置を人物や Policy へ送信する機能は追加していない。
`knowledge-蒼.json`、`knowledge-紗季.json`、`knowledge-蓮.json`、`knowledge-灯.json` は各人自身の knowledge の記録。
他室の行動・発言・位置をこれらの人物別知識ログへ混ぜていない。
蓮の短縮希望は発言前は蓮のみ、発言後は蓮と蒼のみ。現在の engine では同室の紗季への聞き取りが欠落していることも記録した。
4人分の知識監査は1診断の視点別記録であり、4つの独立候補×4視点の作品ではない。

```sh
python3 scripts/cultural_festival_probe.py --out /absolute/path/outside-checkout
python3 -m unittest discover -s tests -p test_cultural_festival.py -v
```

probe は契約の blocker がある場合、出力を保存して exit 2 とする。現時点の exit 2 は意図した結果。
出力先は空の checkout 外ディレクトリを指定する。既存成果物は上書きしない。

制約の根拠: `engine/actions.py:_movement_candidates`、`engine/verbs.py:_move / _target / _share_knowledge`、
`engine/subject.py:Goal`、`engine/sim.py:run`。直接の native capability probe を `capability-probes.json` に保存した。
