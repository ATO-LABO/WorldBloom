# 実行設定

世界設定画面の「実行条件を決める →」、またはホームの「＋ 新しい世界を作る」完了後に開く画面です。GA 実験を1回どう回すかを決めて「設定」として保存し、次の画面で実行します。GA 実験そのもの（候補の生成・重み計算・進化）は LLM を呼び出しません。ただし合理性 κ（下記04.）を 0 より大きくすると、GA の各決定ごとに判定器（ローカル LLM の Ollama、または TypeSafe の Jev。詳しくは[合理性層と Jev](../concepts/rationality-layer.md)）を呼び出します——Ollama は1ラン（個体×seed の組）あたり数十秒以上かかり GPU を使う一方、Jev は1回約0.2秒で GPU を使いません。あらすじ・本文の生成は別段階です（[文章を生成する](generate-text.md)を参照）。

新規作成時は、世界とジャンルが決まっていれば設定名が自動入力されます（例: `2026-09-25 10:00 detective - 星を運ぶ街`。ジャンル部分はジャンルID）。保存済みの条件を選んで複製することもできます（複製時は世界・ジャンルは固定です）。

## 01. 世界と結末

- **世界**: 実行対象の世界を選びます
- **目指す結末**: 既定では世界に設定した「目標の結末」を使います。「別の結末を指定」を選ぶと、結末IDをカンマ区切りで指定でき、そのいずれかに到達すれば成功として扱われます

## 02. 探索の規模

| 項目 | 意味 | 既定値 |
|---|---|---|
| 世代数 | GA の世代数（generations） | 20 |
| 1世代の個体数 | 1世代あたりの個体数（population） | 100 |
| 個体ごとの評価回数 | 個体1体を評価するシード数（seeds） | 3 |

1世代あたりの実行回数は「個体数 × seed数」です。世代を重ねるほど良い経緯が残っていきますが、実行時間もその分伸びます。

## 03. 保存と進化

**結果の保存**（keep）は3通りから選びます。

| 値 | 内容 |
|---|---|
| すべての結果 | all |
| 結末に到達した結果 | reached（既定） |
| 個体ごとに代表1件 | exemplar |

結末に到達した個体が1件もない場合は、keep の設定にかかわらず最良個体の結果を保存します。

**世界の拡張**（world_expansion、[世界の自己拡張](create-world.md#world-expansion)と対応）:

| 値 | 内容 |
|---|---|
| しない（既定） | off。世界は変えません |
| 検知のみ | detect。世界は変えず、行動が空振りした場所・行動を集計するだけです |
| 承認済みの拡張を適用 | expand。承認済みのパッチ（`projects/<world>/patches/*.yaml`）を実行前に適用してから、同じ集計を行います |

**前の実験から引き継ぐ**（evolution.seed_genomes）: 同じ世界・同じジャンルで完了済みの前の実験を選ぶと、その実験の最終地図にいた個体の性格（遺伝子）だけを、この実験の第0世代に使います。前例・地図・volatility の閾値は持ち込まれず、この実験の第0世代で新たに積み上げ直します。既定は「引き継がない」で、そのときは以前と完全に同じ結果（バイト一致）になります。

そのほかの切り替え項目:

- **説明記録**（record_explanations、既定オン）: 候補の選択・根拠・代償・転機をあとから確認できるように記録します
- **共進化**（coevolve、既定オフ）: 敵役側の個体群も並行して進化させます。オンにすると評価回数が2倍になります（主人公パス＋敵役パス）
- **メタ進化**（meta_evolution、既定オフ）: 9つの数値遺伝子に加えて、ルールごとの有効・無効も探索します
- **性格の成長**（evolution.personality_growth、既定オフ）: 物語の中で起きた出来事（勝敗・仲間・裏切りなど）に応じて、主人公の性格がわずかに変わっていくようにします。上の「世界を育てる」とは別物で、世界そのものは変えません。詳しくは[性格の成長](../concepts/personality-growth.md)を参照してください

**世界を育てる**（growth.mode、既定「しない」）: 「エポック連鎖」で実験を自動的に繰り返し、世界そのものを少しずつ育てます。エポック＝世界が1周育つ単位（実験1本を回し、足りない場所の拡張を提案・検査・承認し、使われなかった拡張を枯らす）で、連鎖では前のエポックの性格（地図にいた個体の遺伝子）を次のエポックへ引き継ぎます。「しない」以外を選ぶと「何周回すか」（growth.epochs、1〜10、既定3）と「使われなかった拡張を自動で枯らす」（growth.auto_retire、自動モードは既定オン・手動モードは既定オフ）が現れ、「世界の拡張」は自動的に「承認済みの拡張を適用」に固定されます。「自動で育てる」は提案の検査結果がよければ自動承認・自動淘汰まで行い、「手動で育てる」は承認・却下のたびに画面で止まります（実行画面の「次のエポックへ」ボタンで次に進めます）。

## 04. 合理性（主人公がどれだけ筋の通った手を選ぶか）

ジャンルに `rationality.yaml`（合理性層。詳しくは[合理性層と Jev](../concepts/rationality-layer.md)）があれば、判定器に今接続できるかどうかに関わらず常にこの区画が表示されます。**判定器**は「Jev（TypeSafe、高速・外部送信）」とテンプレートの既定（現状はどのジャンルも Ollama）から選べます。0 にすると合理性判定は行われず、判定器への呼び出しも発生しません。κ を上げるほど、不合理な手段が選ばれにくくなります。

κ と判定器の既定値は、新規作成時にどちらが実際に使えるかで決まります。

| 状態 | 既定の判定器 | κ の既定値 | 実行時間の上限の既定値 |
|---|---|---|---|
| Jev の APIキーが有効 | Jev | 0.45 | 3600秒（変更なし） |
| Jev は無効だが Ollama が使える | テンプレートの既定（Ollama） | 0.6 | 21600秒 |
| どちらも使えない | — | 0（オフ） | 3600秒（変更なし） |

複製・編集では、保存済みの判定器・κ の値がそのまま使われます。κ を 0 より大きくすると、フォームに「判定器を使うラン: ◯◯回」という機械台数に依らない件数だけが表示されます。実際の所要時間はマシン性能（GPU の有無など）で大きく変わるため、見込みは実行画面（`/jobs`）が実行中に出す「残り時間の目安」で確認してください。

## 05. 道筋（寄り道の抑え方） { #05 }

ジャンルに `route.yaml`（道筋層。詳しくは[道筋層](../concepts/route-layer.md)）があれば表示される区画です。主人公が結末へまっすぐ向かう強さを **ρ（0〜1）** で指定します。0（エンジン・CLI・テンプレートの既定）では道筋層そのものが動かず従来どおり無変調、1 に近いほど理由のない寄り道をほとんど選ばなくなります。身体の都合・思い込みによる寄り道は ρ を上げても罰されません。動機表（`motives.yaml`）に一致した寄り道は、その動機に効く遺伝子の強さに応じて扱いが変わり、弱い個体ではほぼ「理由なし」と同じ扱いまで抑えられます。

新規作成画面、および `route.yaml` があるテンプレートでのホーム・世界画面の「1クリックで実行」ボタンでは、ρ に**既定で 1.0** が入ります（κ と違い、ρ は計算コストを増やさないため）。複製・編集では保存済みの値がそのまま使われます。ジャンルを切り替えて対象テンプレートに `route.yaml` が無くなった場合、ρ は自動的に無効（未指定）に戻ります。

## 詳細設定

04.（と、道筋が表示される場合は05.）の区画のあとに、折りたたみで表示される項目です。

- **ジャンル**: 新規作成時のみ選べます（複製時は複製元と同じ）
- **乱数の開始値**（seed_base、既定 0）・**進化の乱数**（ga_seed、既定 1）
- 並列数（GA を同時に何プロセスで進めるか）はここではなく **⚙ 全体設定の「計算」** で指定します（[設定](settings.md)を参照）
- **実行時間の上限**（execution_limits.wall_seconds、既定 3600秒）: この秒数を超えると実行を打ち切ります。κ（合理性判定、上記）を使う場合は既定で 21600 秒に引き上がります

## 実行開始

保存すると、その設定の実行条件画面（`/configs/<設定ID>`）に進みます。「この条件で実行へ →」を押すと実行画面（`/jobs`）が開き、「この設定で GA を回す」を押すと実行が始まります。実行中は世代の進捗バーが表示され、実行を止めても**閉じた世代までの結果は残ります**。実行が終わったら、同じ画面から「同じ設定でもう一度回す」で再実行できます。
