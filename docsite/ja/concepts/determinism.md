# 決定論

WorldBloom の個体評価は純関数として設計されています。**`(world, genome, seed, precedent, engine hash)` が同じなら、出力ログ `layers.jsonl` はバイト単位で一致します。** これは「たまたま再現できる」のではなく、設計の前提であり、回帰テストで守られています。

## なぜ決定論にこだわるか

同じ入力から毎回違う物語が出てしまうと、「なぜこの物語になったのか」を辿る手がかりが失われます。WorldBloom は決定論を守ることで、ある候補がどの世代のどの親から、どんな選択の分岐で生まれたかを[系譜・転機](sifting.md#compare-lineage-turning)として機械的に示せるようにしています。これは LLM だけで物語を作る方式には無い性質です。

## 決定論を成り立たせている3つの約束

1. **乱数は単一の `random.Random(seed)`**: シミュレーション用の乱数と、GA（交叉・突然変異・親選択）用の乱数 `random.Random(ga_seed)` は完全に分離されています。行動選択は候補リストの重みに対して `rng.choices()` を1回呼ぶだけで、それ以外に乱数を消費しません。
2. **候補生成と Policy（遺伝子）は乱数を消費しない**: 行動候補の列挙や、遺伝子による重みの変調（4つの乗数の計算）はすべて決定論的です。「前例表」（[遺伝子](genome.md#novelty-precedent)が参照する正典プライア・アーカイブ前例・自己履歴）も同様に、乱数を使わず世代開始時点で凍結されます。
3. **タイブレークは名前順**: 複数の候補が同点になったときの順序は、常に名前（文字列）の順で決まります。ただし Python の文字列比較は Unicode コードポイント順であり、日本語の直感的な並び（例: 甲・乙・丙）とは一致しない場合があります（実際には「丙 < 乙 < 甲」）。テンプレートを書くときは、この順序が物語上の役割（第一容疑者・第二容疑者など）に対応しているという前提を置かないでください。

## エンジンを変えると物語も変わる

決定論が保証するのは「同じエンジンのコードなら再現できる」ことであり、エンジン自体（`engine/` `gapengine/`）のコードを変えると乱数の消費順序が変わり、同じ genome・同じ seed でも別の物語になります。そのため[QD 格子](qd-map.md)のアーカイブには genome だけでなく、模範ランのログ本体とエンジンのハッシュ（`engine_hash`）を保存します。物語は「genome から作り直せる再現手順」としてではなく、「実際に生まれたログ」として、系譜とともに扱われます。

## 回帰テストで確認する

決定論・中立遺伝子の無変調・前提違反ゼロ・伏線の減点・vitality の遷移などは、次のコマンドで確認できます。

```
python -m unittest discover -s tests -v
```

`engine/` `gapengine/`（GA・分類器・前例表・7層のロジック）を変更したときは、必ずこの回帰テストを通してください。乱数の消費順序が変わるような変更は、設計書にその旨を明記します。
